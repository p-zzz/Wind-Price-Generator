# Load and net position

`actual_load_MW` and `net_position_MW` are **resampled from real DK1 history**
(2023-2025, `data/bootstrap_pool.parquet`), not generated by a parametric model.

## Paired block bootstrap

The simulation calendar is filled block by block (default 168 h = one week). Each
block copies a contiguous stretch of history, with both series taken **from the same
hours** ("paired"), so their real co-movement is preserved. For example, cold spells
raise both load and imports.

## Calendar matching

A block that fills simulated time $t$ is drawn only from historical start hours with:

- the **same local hour of day** as $t$, and
- a **day of year within +/- `bootstrap_window_days`** (default 14) of $t$, treating
  Dec 31 and Jan 1 as neighbours.

So a July scenario gets July load with its daily cycle in the right place. Leap years
are handled on a 365-day basis (Feb 29 counts as Mar 1).

## Gaps and daylight saving

- The source has 139 missing hours out of 26,304. Blocks that would cross one are
  never drawn, so nothing is filled in.
- A block never crosses a daylight-saving change, in the source or in the
  simulation. Blocks are cut short at simulated transitions, so the local clock
  never slips by an hour inside a block.

## Net position sign

Net position is **export-positive, import-negative**, as reported by ENTSO-E. About
half of DK1 hours are imports. Versions before 2026-09 had unsigned values because
of a download bug; see {doc}`../changelog`.

```{note}
Output can only contain values that occurred in 2023-2025. A future load level or
interconnection regime that never happened then cannot appear.
```

API: `generator.bootstrap.paired_block_bootstrap`, `generator.io.load_bootstrap_source`.
